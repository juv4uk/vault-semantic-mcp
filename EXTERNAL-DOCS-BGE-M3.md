# Офіційна документація та найкращі практики для BAAI/BGE-M3

Цей документ зібрано на основі офіційної документації FlagOpen (BAAI) на GitHub, форумів та офіційного хабу HuggingFace, щоб мати повний довідник для роботи з `BGEM3FlagModel` у нашому локальному середовищі.

## 1. Загальна інформація про модель
- **Назва:** BGE-M3 (BAAI General Embedding - Multi-Lingual, Multi-Granularity, Multi-Functionality).
- **Підтримка:** 100+ мов (включно з українською, гінді, англійською).
- **Довжина контексту:** до 8192 токенів (проте в нашому `config.json` наразі стоїть `max_length=256` для економії пам'яті).
- **Мультифункціональність:** Модель одночасно генерує:
  1. *Dense vectors* (густі вектори для косинусної подібності)
  2. *Sparse/lexical weights* (субсловникові ваги для точкового пошуку)
  3. *Multi-vector (ColBERT)* взаємодію для тонкого ранжування.

## 2. Офіційні приклади використання (FlagEmbedding)

Встановлення (у нашому віртуальному середовищі вже виконано):
`pip install -U FlagEmbedding`

**Базовий код генерації (як це працює під капотом нашого `embeddings.py`):**
```python
from FlagEmbedding import BGEM3FlagModel

# use_fp16=True критично для GTX 1050 Ti (4GB VRAM), зменшує пам'ять вдвічі
model = BGEM3FlagModel('BAAI/bge-m3', use_fp16=True)

sentences = ["Словосполучення для тестування", "Інший текст"]

# Повертає словник: {'dense_vecs': [...], 'lexical_weights': [...], 'colbert_vecs': [...]}
embeddings = model.encode(sentences, batch_size=12, max_length=256)['dense_vecs']
```

## 3. Рекомендації з форумів щодо оптимізації (WSL2 + 4GB VRAM)

1. **batch_size:**
   - Офіційно рекомендується `batch_size=12` або `24` для GPU з малим об'ємом пам'яті. У нашому пайплайні стоїть `24`, що якраз займає близько 1.1 - 1.5 ГБ VRAM у піку.
2. **CPU Bottlenecks у WSL2:**
   - Проблема: PyTorch при токенізації (через `transformers`) часто створює надлишкову кількість CPU-потоків. Це може призвести до "заморожування" системи (що в нас і сталося).
   - *Рішення:* Перед запуском Python-скрипта експортувати змінні:
     ```bash
     export OMP_NUM_THREADS=2
     export MKL_NUM_THREADS=2
     export PYTORCH_CUDA_ALLOC_CONF=expandable_segments:True
     ```
3. **Sparse (Lexical) Weights:**
   - Користувачі форумів (та репозиторію BAAI) зазначають, що лексичні ваги BGE-M3 не видають цілі слова, а лише BPE-токени (наприклад, `_it`, `i`, `hasa` замість `itihasa`). 
   - *Висновок для нашої архітектури:* Їх не можна використовувати напряму для "генерації" тегів чи нових слів в Онтологію. Модель BGE-M3 можна використовувати **тільки для розрахунку косинусної відстані** (`dense_vecs`) з уже наявними словами.

## 4. Обмеження моделі
- BGE-M3 не генерує текст. Вона є виключно "енкодером" (Encoder-only architecture, типу RoBERTa/XLM-R). Будь-які ідеї щодо того, щоб модель "сама придумала тег", не працюватимуть математично без додаткового LLM-декодера (як-от Llama або API-сервіси типу Sarvam).
